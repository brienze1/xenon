# Contract: `EnvironmentService` Wails binding (XEN-011)

Binding struct: `internal/infra/server/binding/environment.go` (`EnvironmentService`).
Controller: `internal/integration/entrypoint/controller/environment_manage.go`
(`EnvironmentManageController`).

## New method — `EnvironmentService.Reorder`

Moves one environment to a position and returns the whole, re-arranged list.

### Request — `dto.ReorderEnvironment`

```json
{ "local_id": "<workspace local id>", "id": "<environment id>", "index": 0 }
```

| Field | Rule | Failure |
| --- | --- | --- |
| `local_id` | required, not blank | `400 ENV-17400` |
| `id` | required, not blank | `400 ENV-17400` |
| `index` | integer ≥ 0; 0 = first environment (right under Globals); ≥ count → last | `400 ENV-17400` when negative |

### Response — `dto.EnvironmentList` (unchanged shape)

```json
{
  "active_id": "01JA…D1",
  "environments": [
    { "id": "01JA…P1", "name": "PROD", "color": "red", "confirm_before_send": true, "error": null },
    { "id": "01JA…D1", "name": "DEV",  "color": "none", "confirm_before_send": false, "error": null }
  ]
}
```

Arranged per FR-007 (stored order → other readable environments alphabetically → broken files by
file name). `active_id` is unchanged by a reorder.

### Errors

| Case | Code |
| --- | --- |
| Unknown workspace `local_id` | existing workspace-registry not-found code |
| `id` names no readable environment (missing or broken) | `404 ENV-01404` |
| `workspace.yaml` cannot be written | `WKS-26500` (file error, existing) |
| `workspace.yaml` cannot be parsed | `422 WKS-15422` (existing) |

### Side effects

- Writes `environments.order` in `workspace.yaml` (research R4/R6) unless the resulting order
  equals the current arranged order (then nothing is written).
- Emits `variables:changed` with the moved environment's scope (research R9).
- Triggers auto-sync "saved" like `Update`.
- Never touches environment files, local current values, the vault, or the active environment.

## Changed behaviour of existing methods

| Method | Change |
| --- | --- |
| `List` | Arranged by the stored order (FR-007). Never writes. |
| `Create` | After the file is written, `environments.order` = arranged ids + new id (FR-009). |
| `Duplicate` | Same as `Create` for the copy's id (FR-009). |
| `Delete` | If the stored order names the id, it is removed and written (FR-012); otherwise no write. |
| `Update` (rename/settings) | No change to the order (FR-011). |

## Import (`ImportService.Import`, environments)

Handled in `importVariablesWriter.environment`
(`internal/application/service/import_variables_writer.go`):

| Resolution | Order |
| --- | --- |
| No clash / Keep both | arranged ids + imported id, appended in the order items are imported |
| Replace | replaced id swapped for the imported id in place |
| Skip | unchanged |

Each item re-lists environments and computes its new order before any file is written or
deleted (targets are resolved once per batch, so the pre-resolved list is stale), and writes the
order after the environment file is saved. An import whose order write fails reports the item as failed
with the workspace file error and leaves the already-written environment file in place (the
environment then shows in the alphabetical tail, which is a valid state). Whole-workspace Xenon
imports copy `workspace.yaml`, so they keep the source's `environments.order`.

## Frontend wrapper — `frontend/src/platform/services/environments.ts`

```ts
/** Moves the environment to `index` among the readable environments and returns the new list. */
export function reorderEnvironment(localId: string, id: string, index: number): Promise<EnvironmentList>
```

Implemented with `EnvironmentService.Reorder({ local_id, id, index })` → `toEnvironmentList`.
The generated binding is regenerated by `make` (Wails bindings), never edited by hand.
