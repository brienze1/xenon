# Research: Shell and Storage (Stage 1)

All findings verified on 2026-10-09 (module proxy, GitHub releases, npm registry, Wails v3 source,
and a throwaway `wails3 init` + `wails3 generate bindings` run).

## R1. Desktop shell — Wails v3 version and scaffold
- **Decision**: Pin `github.com/wailsapp/wails/v3@v3.0.0-beta.28` (Go module and `wails3` CLI) and
  `@wailsio/runtime@3.0.0-beta.28`. Scaffold with `wails3 init -n xenon -t react
  -mod github.com/brienze1/xenon` (in beta.28 the `react` template **is** React + TS + Vite;
  `react-ts` no longer exists). Bump React 18.2 → 19 after scaffolding (the Vercel composition
  skill assumes React 19 APIs). Go ≥ 1.25.
- **Rationale**: PRD says pin the latest beta; betas ship every few days, so floating versions
  would break builds. Generated layout (`build/`, `frontend/`, `Taskfile.yml`, `build/config.yml`)
  is kept as Wails expects it.
- **Alternatives**: Wails v2 (stable but no typed events/cancellable calls, PRD chose v3); Tauri
  (Rust, rejected by PRD).

## R2. Bound services, errors and cancellation
- **Decision**: Thin binding structs in `internal/infra/server/binding/` registered with
  `application.NewService`. Every method takes `ctx context.Context` first, so JS
  `promise.cancel()` cancels the Go context — this implements Send → Cancel with no extra API.
  App-wide `Options.MarshalError` serialises `errs.BaseError.ToDto(txId)` so the frontend gets the
  skill's `{ error: { id, code, description, error_details } }` JSON in `RuntimeError.cause`.
  Bindings generated with `wails3 generate bindings -ts -clean` into `frontend/bindings/` (git
  ignored; regenerated by `make bindings` and checked for drift in CI).
- **Rationale**: Matches the skills' split: the Wails binding plays the router's role (infra), the
  controller in `internal/integration/entrypoint/controller/` keeps the full controller pattern
  (validate → `ToEntity` → application adapter → response DTO, error handler, panic recovery).
- **Alternatives**: Bindings as controllers directly (would put Wails types next to integration
  code — violates "no framework types in integration"); per-service `MarshalError` (duplication).

## R3. Backend → UI events
- **Decision**: `application.RegisterEvent[T](name)` in `internal/infra/server/event/` with
  constant names, so generated TS types check names and payloads. Integration code emits through a
  publisher (`internal/integration/publisher/`) over an `EventEmitter` interface whose Wails
  implementation (`app.Event.Emit`) lives in `internal/infra/adapter/` and is injected with a
  setter (outer boundary), so BDD can capture events with a mock.
- **Events (stage 1)**: `workspace:tree-changed {workspaceId}`, `request:changed-on-disk
  {workspaceId, requestId, deleted}`, `workspace:folder-missing {workspaceId}`.

## R4. Large response bodies
- **Decision**: Response bodies are never sent through the JSON bridge above 1 MB. The Go request
  service keeps each tab's last body (memory ≤ 5 MB, else a temp file) and a small
  `http.Handler` service mounted with `ServiceOptions.Route = "/xenon/response"` streams it:
  `GET /xenon/response/{tabId}` (raw bytes, original content type). The UI loads bodies via
  `fetch()` from that same-origin route, wrapped in `frontend/src/platform/`.
- **Rationale**: SC-003 (50 MB in ≤ 2 s) is not achievable through JSON-encoded binding returns;
  the asset-server route is local IPC inside the app, not network access by React (constitution
  III holds — Go still owns the data).
- **Alternatives**: chunked binding calls (`GetBodyChunk(offset)`) — slower, more code.

## R5. YAML round-trip and file format
- **Decision**: `go.yaml.in/yaml/v3@v3.0.5` (maintained fork; `gopkg.in/yaml.v3` was marked
  unmaintained in April 2025). Persistence decodes each file to a `yaml.Node`, decodes the known
  part into the model struct, and on save **patches** the owned keys back into the node tree
  (keeps unknown keys, their order and most comments), then encodes with indent 2. Models
  implement ordered output by building the node in the contract's field order, so struct field
  order (which `betteralign` rewrites) never affects file key order.
- **Alternatives**: struct-only marshal (loses unknown fields and churns key order with
  betteralign); yaml v4 (still RC).

## R6. Atomic writes
- **Decision**: In-house `pkg/fileutils.WriteFileAtomic(path, data, perm)`: temp file in the same
  directory (`.<name>.xenon-tmp`), write, `Sync`, `Close`, `os.Rename` over target (Go uses
  `MoveFileEx(REPLACE_EXISTING)` on Windows), retrying the rename up to 5× with 20 ms backoff on
  Windows sharing violations; temp file removed on any failure.
- **Alternatives**: `google/renameio/v2` (no Windows support), `natefinch/atomic` (fine, but 2021
  and ~30 lines to own instead).

## R7. File watching
- **Decision**: `github.com/fsnotify/fsnotify@v1.10.1`, recursive by walking the workspace tree and
  adding directories on Create; ignore `Chmod`, temp files (`*.xenon-tmp`) and Xenon's own writes
  (the persistence layer records path+hash of its own writes for 2 s); debounce 150 ms per path.
  Only the **active** workspace is watched. On overflow/error → full reload of the tree.
- **Rationale**: Covers FR-017 on all three OSes. kqueue on macOS uses one fd per file — a
  1,000-request workspace is ~1,100 fds, within default limits; documented as a known limit.
- **Alternatives**: `rjeczalik/notify` (FSEvents, recursive) — less maintained; polling — slow.

## R8. Move to trash
- **Decision**: `github.com/Bios-Marcel/wastebasket/v2@v2.0.3` on Windows and Linux; on macOS a
  small cgo shim calling `NSFileManager trashItemAtURL` (wastebasket shells out to `osascript`,
  which is slow, needs an AppleEvents permission and breaks on paths containing `"`). Both behind
  one `Trash` interface in `internal/infra/adapter/trash*.go` with a setter.

## R9. HTTP engine and timings
- **Decision**: One `http.Client` per send with a fresh `http.Transport`
  (`DisableKeepAlives: true`, proxy from environment, TLS `InsecureSkipVerify` per the request's
  Verify SSL setting, redirect policy per Follow redirects, timeout per request) and
  `httptrace.ClientTrace` (DNSStart/Done, ConnectStart/Done keyed by address, TLSHandshakeStart/
  Done, WroteRequest, GotFirstResponseByte). Download = end of body read − first byte.
  Accept-Encoding gzip/deflate/br is decoded (br via `github.com/andybalholm/brotli`), size is the
  wire size, headers shown as received.
- **Rationale**: Postman shows full DNS/connect/TLS for every send; connection reuse would hide
  them. Per-send transport is cheap for an interactive client.
- **Error mapping** (`ErrorKind`): `*net.DNSError` → dns; `ECONNREFUSED` → connection_refused;
  `context.DeadlineExceeded`/`net.Error.Timeout()` → timeout; `x509.*`/`tls.*` → tls;
  `context.Canceled` → cancelled; missing body file → missing_file; URL parse → invalid_url.

## R10. Local app data
- **Decision**: `os.UserConfigDir()/Xenon` (Linux `xenon`), overridable by property
  `XENON_DATA_DIR` (used by BDD). Temp bodies in `os.TempDir()/xenon-<pid>/`. Window bounds saved
  on move/resize (debounced) and restored with clamping to `app.Screen` (Wails has no built-in
  persistence). `SingleInstance` enabled (`UniqueID: "dev.brienze.xenon"`), second launch focuses
  the existing window.

## R11. Testing stack
- **Decision**: Backend: `github.com/cucumber/godog@v0.16.0` BDD per the testing skills, steps
  calling the **binding structs in-process** (no window), real temp directories as workspace roots
  (`XENON_DATA_DIR` + per-scenario temp dirs), `mock.ApiMock` (httptest) as the request target,
  `mock.Time` via `timeutils`, mocks for Trash, EventEmitter and the native dialog picker via
  setters. Frontend: Vitest + React Testing Library + jsdom, `platform/` mocked.
- **Gate tooling**: keep the makefile skill's pipeline (goimports, betteralign, vet, deadcode,
  tests, coverage ≥ 65 %, gremlins mutation ≥ 72 %, efficacy 100 %). Replace `nancy` (needs Sonatype
  credentials) with `govulncheck` in `dependency-check` — same intent, no account (constitution I).
- **deadcode note**: binding methods are reached by reflection; BDD calls them, so `deadcode -test`
  sees them as used.

## R12. Frontend libraries
- **Decision** (pinned at scaffold time, exact versions recorded in `package.json`): React 19,
  TypeScript 5, Vite (from template), Zustand 5, CodeMirror 6 (`@codemirror/view`, `state`,
  `lang-json`, `lang-xml`, `lang-html`, `lang-javascript`, `search`, `language` folding),
  `@dnd-kit/core` + `@dnd-kit/sortable` (tab reordering now, sidebar in stage 5),
  `@tanstack/react-virtual` (sidebar tree and history lists), `react-markdown` (Info panel
  description), ESLint 9 flat config + `eslint-plugin-boundaries`, Vitest, React Testing Library.
  Fonts self-hosted in `frontend/public/fonts/`: Inter, JetBrains Mono, and **Permanent Marker**
  (Apache 2.0) as the marker display font.

## R13. Cross-platform CI
- **Decision**: GitHub Actions matrix `macos-latest`, `windows-latest`, `ubuntu-24.04`:
  setup-go (1.25+), setup-node (LTS), `go install …/wails3@v3.0.0-beta.28`, Linux apt
  `build-essential pkg-config libgtk-4-dev libwebkitgtk-6.0-dev`, then `make validate`,
  frontend `npm run check`, `make build`. Bindings drift check on Linux.
